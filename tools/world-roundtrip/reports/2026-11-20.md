# First world round-trip report, 2026-11-20

Roadmap G7-03 and G7-04. `tools/world-roundtrip/roundtrip.py` ran the G7-01 fixture world
(vanilla 26.3, DataVersion 5023) through PEX, then vanilla 26.3, then PEX again, and set time,
weather, a scoreboard, a team, a border and a forced chunk on a fresh PEX world before restarting
it and opening it in vanilla. PEX was `alpha` 8f59e0782 plus `fix/saved-data-dataversion`
(DataVersion beside `data`, border doubles), both found by the first runs of this tool. The full
generated report follows this summary; `known-losses.txt` next to the tool lists every difference
group below with the piece that fixes it, and the CT 117 nightly stage `30-world-roundtrip` fails
on anything it doesn't list.

## What vanilla did with PEX's save

- Block palettes: vanilla could not read any section PEX had saved. PEX writes palette entries as
  `{Name, Properties}`; 26.3 expects a bare id string or `{id, properties}`, logs "Recoverable errors
  when loading section ... using default" (about 800 lines) and loads the section as air. Every
  block PEX re-saved is lost in vanilla, and with them the lab's 53 block entities. This is G7-05,
  and it is the largest loss the round trip found.
- POI: PEX left the fixture's `poi/r.0.0.mca` byte-identical (it never rewrote it); vanilla
  rewrote it with the same records. No POI difference.
- `data/` files: before the fix, vanilla refused PEX's `game_rules.dat` and `world_clocks.dat`
  ("Failed to parse saved data": `DataVersion` was inside `data`, where vanilla reads it as a rule
  and a clock id), so a world opened in vanilla after PEX lost its game rules and its time. With the
  fix, vanilla reads every data file. `scoreboard.dat`, `chunk_tickets.dat`, `world_border.dat`,
  `weather.dat`, `world_clocks.dat` and `ender_dragon_fight.dat` keep their content both ways.
  `raids.dat`, `stopwatches.dat`, `random_sequences.dat`, `custom_boss_events.dat`,
  `scheduled_events.dat`, `command_storage` and `maps/` survive because PEX leaves them untouched
  (it doesn't read them yet; G7-16 to G7-20).
- Small format differences vanilla doesn't mind: PEX writes default scoreboard and wandering trader
  fields that vanilla omits, the experimental `max_minecart_speed` game rule, the dragon fight's
  `gateways` as an int array instead of a list and an empty `respawn_crystals` (G6-19), and the
  level.dat keys 26.3 moved into data files (G7-13).

## What PEX lost from the fixture

- Scheduled block and fluid ticks of chunks below full status (about 3,000 entries), and their
  `structures`, `PostProcessing`, `Heightmaps`, `LastUpdate` and proto-chunk `entities`: G7-06 and
  G7-07, decided by D7-1.
- Block entity keys (`components`, `keepPacked`, cooking speed, `RecipesUsed`, `CustomName` on some
  types): G7-25. Item components such as map decorations and `item_name` forms: G7-23. Entity
  keys and attributes: G7-24.
- Light: PEX relights loaded chunks and writes sky light layers vanilla leaves out. Not a loss.

## Fresh world checks

All passed: after a PEX restart and again in vanilla, the overworld clock read 6000 and up,
`weather.dat` was thundering with a thunder time in 1..3000, `#roundtrip` had score 31 in
`roundtrip_obj`, team `roundtrip_team` existed, the border was 1234 wide and chunk 12,12 was still
force-loaded. Without the DataVersion fix, vanilla lost the time.

## Commands PEX lacks, found on the way

- `scoreboard objectives list`.
- PEX still accepts `time query daytime`, which 26.3 removed (`daytime` is a timeline id there).
