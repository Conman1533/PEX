# Bedrock parity roadmap

Goal: a Bedrock player on the current client (1.26.60, protocol 2225) joins PEX directly, with no proxy, and plays alongside Java players with the same game. Same world, same rules, same items and drops, same mobs, same chat, commands and plugins. Where Bedrock's client can't show something the Java way (advancements, some GUIs), it gets the closest native Bedrock equivalent instead of nothing.

This builds on Goal 8 of `docs/ROADMAP-2.0.md`. Its answer to D8-1 kept 2.0 at "experimental with honest gaps" (G8-01 to G8-12). This roadmap is everything after that, up to full parity, and it takes over G8-01 to G8-22 so the work has one owner. Its Current state section (2026-11-19) is the survey this plan starts from and isn't repeated here.

IDs are `BP<stage>-<nn>`. A piece that already has a Goal 8 ID keeps it in brackets. Each piece names its branch and what proves it done. Stages are ordered; pieces inside a stage mostly aren't.

## How parity is measured

Three yardsticks, used together:

1. **The bot.** A Rust Bedrock client in `tools/pumpkin-tester` (BP0-01) joins over NetherNet exactly as a phone does, next to the Java `HeadlessBot`. Every piece below that a bot can observe is proven by a bot test that fails before the change.
2. **The coverage table.** `docs/BEDROCK-COVERAGE.md` (BP0-03) lists every clientbound Java send in `pumpkin-core` and every serverbound Bedrock packet, each marked covered, partial, native-equivalent or gap. A script regenerates the call-site list so a new Java-only send can't slip in unnoticed.
3. **Geyser as the floor.** Paper 26.3 with Geyser and Floodgate is what Bedrock players get today. PEX should never do worse than it for the same client, and should do better where Geyser is limited by being a proxy (no double translation, real block and item ids for Bedrock-only content, server-side knowledge of Bedrock players).

Real-client checks (a phone or console on 1.26.60) stay Neon's. Each stage ends with a short human checklist for what a bot can't see: rendering, sounds, GUI layout.

### Progress, 2026-11-20

- BP0-01 and BP0-02 are on `test/bedrock-bot`: the bot joins over real NetherNet/WebRTC and 12 checks pass (join, chunks, each edition sees the other, chat both ways, a Bedrock command reaching Java, movement both ways, creative block break both ways, leave). Still open: block placing and swing checks, the `bedrock-client` feature (the bot keeps its readers in the tester for now), and the 10-runs-in-a-row bar.
- BP0-03, first half: `docs/BEDROCK-COVERAGE.md`, generated by `tools/bedrock-coverage.py --gophertunnel <checkout>`, lists every packet gophertunnel knows at 2225 and whether PEX encodes, sends, decodes and handles it. At 2225 PEX has structs for 61 of 192 clientbound packets and uses 50, and decodes and handles 30 of 91 serverbound ones. The Java call-site gate is the other half and is still open.
- BP0-05, first half: every wire change gophertunnel made between 2169 and 2225 is already in PEX (passenger-of-block on AddActor and AddPlayer, MoveActorDelta ticks, StartGame's editor migration version, PlayFab ids in the player list, single-layer optionals in PlayerAuthInput). The `Last verified for v2169` comments in `pumpkin-protocol` are stale, not the layouts. Block positions are zigzag VarInts on every packet at 2225, so the old unsigned-y worry doesn't apply.
- BP0-05, second half, on `test/bedrock-wire`: with `PUMPKIN_TESTER_BEDROCK_DUMP=<dir>` the bot writes every packet it receives to a file, and `tools/bedrock-wirecheck` (Go, gophertunnel at 2225) decodes each one with gophertunnel's own codec. All 832 packets of 33 types from a `--bedrock-only` run decode with no bytes left over. Dropping the tick field from `CMoveActorDelta` makes the Rust tests still pass and the wire check fail 140 packets.
- Stage 1 on branches: BP1-01 on `fix/bedrock-login-checks`, BP1-03 on `fix/bedrock-bad-packet-kick`, BP1-02 on `fix/bedrock-connection-limits` (each stacked on the one before). The bot suite is at 24 checks.
- BP1-04 on `fix/bedrock-oidc-keys` (off alpha, independent): OIDC keys are fetched only with Bedrock on, retried with backoff after a failure, and refetched (at most once a minute) when a token names an unknown key. Five unit tests against a local key server; three fail with the old fetch-once behaviour.
- BP1-05 on `fix/bedrock-deploy-ports` (off alpha, independent): compose publishes TCP and UDP 19132, the Dockerfile exposes them, and both eggs map a `BEDROCK_PORT` variable into the NetherNet address. 19133 (RakNet IPv6) is no longer used. Checked by applying the egg rewrite to a real config: `/v1/join` answers 200 on the remapped port. `docker compose up` itself is still to run.
- BP1-06 on `perf/skin-fetch-off-join` (off alpha, independent): `Player::new` no longer downloads the Java skin (it blocked the join with no timeout, Bedrock on or off). The download runs on a server task after the join, only with Bedrock on, capped at 5 s and 64 KiB, and the result goes to Bedrock viewers in a new `CPlayerSkin` (93), which gophertunnel decodes cleanly. Stage 1 now has a branch for every item.
- BP2-01, first part, on `fix/bedrock-movement` (stacked on `fix/bedrock-connection-limits`): Bedrock players took no fall damage at all; the auth-input handler now runs `fall`, `jump` (on `StartJumping`), movement statistics, footstep game events, elytra landing and the idle timer like Java's `handle_position`. Bot check: a 10.5-block fall costs the Bedrock and Java bots the same 7 health. Swim state, crawling, sneak and sprint flags and mounts are still open.
- BP2-01, second part, on `fix/bedrock-pose-flags` (stacked on `fix/bedrock-movement`): Bedrock players never saw anyone crawl, because Bedrock shows crawling with its own `CRAWLING` actor flag and PEX never set it (the Java pose number goes in `POSE_INDEX`, which Bedrock uses for armor stands). Bedrock sneak and sprint input skipped `PlayerToggleSneakEvent` and `PlayerToggleSprintEvent`, so plugins couldn't see or cancel them. Bot checks: sneaking, sprinting and crawling each way between the Java and Bedrock bots (9 checks). Swimming as Bedrock reports it and mounts are still open.
- Found on the way, on `fix/suffocation-predicates` (off alpha, not Bedrock-specific): leaves, glass and copper grates suffocate players since the Oct 17 `blocks.json` regeneration dropped #4049's 45 suffocation predicates. Restored, with a test. The Extractor needs to emit the field.

## Decisions for Neon

None of these block Stage 0 or 1. Each has a recommendation that work proceeds on until Neon says otherwise.

- **DP-1 Bedrock UUIDs.** (a) keep PEX's MD5 of `pocket-auth-1-xuid:<xid>`; (b) Floodgate's `UUID(0, xuid)` so player data from a Paper+Geyser+Floodgate server carries over, and plugins that know Floodgate UUIDs work; (c) offline UUID of the prefixed name. Recommended: (b). Bedrock joins on alpha don't work with a current client yet, so there are almost no existing files to move.
- **DP-2 Name prefix for Bedrock players.** Empty today, so a Bedrock gamertag can take a Java player's name. Recommended: `.` like Floodgate, on new configs only.
- **DP-3 Bedrock skins for Java players.** Needs a third-party signing service (GeyserMC's global API or MineSkin), which sees every Bedrock skin. Recommended: opt-in, off by default.
- **DP-4 Xbox friends join.** Needs a Microsoft account signed in on the server. Recommended: build it, opt-in.
- **DP-5 Account linking.** Recommended: yes, after Stage 4, with a link code shown in-game, no external service.
- **DP-6 Version policy.** Recommended: current and previous protocol (BP6-02).
